## 6. Page Requirements

### 6.1 Upload
*Headline: "Good {morning / afternoon / evening}, *analyst*". Subtitle: "Drop in a messy file and let's see what's inside."*

- **FR-UP-01** A large drop zone in the center. Drag over highlights it. Click opens the file picker. It accepts `.csv`, `.tsv`, `.txt` (delimited), `.sqlite`, `.sqlite3` and `.db`.
- **FR-UP-02** Validation happens in the browser first and again on the server:
  - wrong extension: "This file type is not supported. Use CSV, TSV or SQLite."
  - larger than MAX_UPLOAD_MB: states the limit and the file size
  - empty file (0 bytes): "This file is empty."
  - headers only, no data rows: "Found column names but no data rows."
  - more than 200 columns: "Too many columns (max 200)."
  - more than 1,000,000 rows: rejected. Above 200,000 rows a warning says analysis may be slower
- **FR-UP-03** Encoding is detected in this order: UTF-8, UTF-8 with BOM, Windows-1252, Latin-1. The detected encoding is shown on the summary. If characters look broken after decoding (for example `Ã©`), a warning is shown.
- **FR-UP-04** The delimiter is detected among comma, semicolon, tab and pipe. If the first row looks like data (every cell numeric or date), a modal asks "Does your first row contain column names?". "No" generates `column_1`, `column_2` and so on.
- **FR-UP-05** Column names are normalized for SQL: trimmed, lower-cased, spaces and symbols replaced by underscores, repeated underscores collapsed, `col_` prefix if the name starts with a digit, `column_N` for empty headers, `_2` suffix for duplicates. A mapping of original to normalized name is stored and shown in the UI.
- **FR-UP-06** Each column gets a detected type: integer, decimal, text, date, boolean, or categorical (a text column with few distinct values). A column is typed number or date only if at least 80% of non-blank values parse; otherwise it is text and flagged "mixed". Types appear as small tag chips in the preview header.
- **FR-UP-07** A "Try sample dataset" button offers two samples: "SaaS subscriptions" and "E-commerce orders" (both from the generator in Section 13). If the sample files are missing, the server generates them on demand.
- **FR-UP-08** A progress bar shows upload and parsing, with a Cancel button.
- **FR-UP-09** After loading, summary cards show Rows, Columns, File size and Health score (quick estimate), plus small notes for encoding and delimiter. Numbers count up on first display.
- **FR-UP-10** A preview table shows the first 8 rows. It scrolls horizontally, keeps the first column visible, truncates long text with a tooltip, and shows blanks as a faint dash.
- **FR-UP-11** If a file with the same name, size and content hash was already uploaded, ask "This file is already loaded. Replace it or keep both?".
- **FR-UP-12** SQLite files are verified by their header bytes. All user tables and views are listed with row counts. The user picks one primary table for Data Health and Insights. Ask AI sees every table and may join them. A SQLite file with no user tables, or a corrupted or encrypted one, gives a clear error.
- **FR-UP-13** The table name comes from the file name, lowercased and sanitized. Name collisions get a numeric suffix.
- **FR-UP-14** A "Recent datasets" list under the drop zone supports open, rename and delete (with confirmation). Up to 20 datasets are kept. Deleting removes all its files, its history and its report data.
- **FR-UP-15** Rows with more or fewer cells than the header are padded or trimmed. The summary reports "N rows had an unexpected number of columns and were adjusted".
- **FR-UP-16** A binary file renamed to `.csv` is detected (null bytes, no text structure) and rejected with "This does not look like a text file."
- **FR-UP-17** If several files are dropped at once, only the first is used and a toast explains this.
- **FR-UP-18** Cells starting with `=`, `+`, `-` or `@` are stored unchanged but escaped when any export is produced (FR-ASK-13).
- **FR-UP-19** A "Continue to Data Health" primary button is disabled until a dataset is loaded.
- **FR-UP-20** Parsing a 50,000-row file completes within 5 seconds.

### 6.2 Data Health
*Headline: "How healthy is your *data*?"*

- **FR-DH-01** The health check runs automatically when a dataset is loaded (within 3 seconds for 50,000 rows). The result is saved as a snapshot. A "Re-run" button recomputes it.
- **FR-DH-02** The checks performed:

| # | Check | How it is detected |
|---|---|---|
| 1 | Missing values | Blank, whitespace only, or placeholders: NA, N/A, null, none, nan, -, ?, unknown (case-insensitive) |
| 2 | Duplicate rows | Exact duplicates across all columns |
| 3 | Duplicate keys | Same value in an ID-like column (name contains id, code, key, number) with different other values |
| 4 | Mixed date formats | A date column where values match more than one format pattern |
| 5 | Mixed types | A column where 5% to 80% of values fail to parse as the dominant type |
| 6 | Inconsistent categories | Values that differ only by case or surrounding whitespace |
| 7 | Numbers stored as text | Currency symbols, thousands separators or percent signs |
| 8 | Inconsistent booleans | A mix of 1/0, yes/no, true/false, y/n |
| 9 | Outliers | Method in FR-IN-04 |
| 10 | Impossible values | Negative or zero values in columns whose names suggest they cannot be (price, mrr, amount, quantity, seats, age, salary, revenue) |
| 11 | Invalid emails | Values in email-like columns without a valid pattern |
| 12 | Logical date errors | In paired columns (signup/churn, start/end, order/ship) the later date is earlier than the first |
| 13 | Whitespace | Leading or trailing spaces in text |
| 14 | Near-empty columns | More than 60% blank |
| 15 | Constant columns | Only one distinct value |
| 16 | Encoding glitches | Characters such as `Ã©` or the replacement character |

- **FR-DH-03** Health score (0 to 100) is 100 minus these penalties, rounded:

| Category | Max penalty | Penalty formula |
|---|---|---|
| Completeness | 30 | 30 × min(1, missing cell ratio ÷ 0.15) |
| Uniqueness | 15 | 15 × min(1, duplicate row ratio ÷ 0.05) |
| Consistency | 25 | min(25, 5 × number of columns with a consistency issue, checks 4 to 8 and 13) |
| Validity | 20 | 20 × min(1, invalid cell ratio ÷ 0.02), checks 10 to 12 |
| Outliers | 10 | 10 × min(1, outlier value ratio ÷ 0.03) |

  Bands: 85 and above is "Healthy" (green), 60 to 84 is "Needs attention" (amber), below 60 is "Poor" (red). The five categories show as mini progress bars under the donut.
- **FR-DH-04** The top area shows a donut with the score and band label, and four stat cards: Missing values (cells and percent), Duplicate rows, Mixed formats (number of columns) and Outliers (number of values). Clicking a stat card filters the column table to related columns.
- **FR-DH-05** The column table shows: original and normalized name, detected type, a missing-percent bar, distinct count, three example values and issue badges. It is sortable and searchable, with an "Only columns with issues" filter. Clicking a row opens a drawer with the top 10 values as bars, examples of bad values and the suggested fix.
- **FR-DH-06** The "Suggested fixes" panel lists each fix with a checkbox, a plain description, the number of affected rows and a risk tag (Safe or Review). Safe fixes are ticked by default. Review fixes are unticked, except the duplicate-key fix, which is ticked.

| Fix | Default | Risk |
|---|---|---|
| Trim whitespace | On | Safe |
| Turn placeholders (N/A, null, -) into true blanks | On | Safe |
| Standardize category spelling and case (merge to the most frequent form) | On | Safe |
| Convert numbers stored as text to numbers | On | Safe |
| Standardize dates to YYYY-MM-DD | On | Safe |
| Standardize booleans to 1 and 0 | On | Safe |
| Remove exact duplicate rows | On | Safe |
| Remove duplicate keys (keep the first occurrence) | On | Review |
| Set impossible values to blank | Off | Review |
| Set invalid emails to blank | Off | Review |
| Set an end date that is before its start date to blank | Off | Review |
| Fill blank numbers with the median | Off | Review |
| Fill blank text with "Unknown" | Off | Review |
| Add an `is_outlier` flag column (rows are never removed) | Off | Review |
| Drop columns that are more than 60% blank | Off | Review |

  Rows are never deleted for having missing values.
- **FR-DH-07** Ambiguous dates: when day and month cannot be told apart (for example 03/04/2024), the majority pattern in the column decides. If there is no majority, the fix is marked Review with a note and the date is read as day first.
- **FR-DH-08** The "Auto-clean data" button runs the ticked fixes in a fixed order, writes the `<name>__clean` table, never touches the raw table, records a cleaning log and switches the active view to cleaned. The score animates from the old to the new value, and a toast says what changed.
- **FR-DH-09** A "Preview changes" link shows up to 20 before and after examples per fix, without applying anything.
- **FR-DH-10** A Before / After toggle switches the donut, stat cards and column table between the raw and cleaned snapshots, and shows a short diff (for example "rows 1,049 to 1,024, missing values 612 to 140").
- **FR-DH-11** The cleaning log lists each fix, rows affected and examples. It can be downloaded as `.md` and is included in the report.
- **FR-DH-12** "Use raw data" and "Use cleaned data" radio buttons switch the active view at any time. "Re-clean with different options" replaces the clean table.
- **FR-DH-13** Cleaning is deterministic and idempotent: running it twice with the same options gives the same result.
- **FR-DH-14** If no fix is ticked, the Auto-clean button is disabled with a hint. If the score is 95 or higher and nothing is flagged, the page shows "Your data looks great".
- **FR-DH-15** Cleaning large files shows progress and can be cancelled. A cancelled run leaves no partial clean table.
- **FR-DH-16** For SQLite uploads with several tables, a table selector sits at the top of the page. Each table has its own snapshot and clean copy.
- **FR-DH-17** A dataset with fewer than 20 rows shows a warning that statistics may be unreliable.
- **FR-DH-18** A "Continue to Ask AI" button sits at the bottom of the page.

### 6.3 Ask AI
*Headline: "Ask your data, *anything*". Layout: see the wireframe in Section 4.6. A wide conversation card on the left, a narrow right column with the Self-correction card above the Generated SQL card, and a floating question bar with suggestion chips at the bottom.*

- **FR-ASK-01** The question box is single line and grows to 5 lines. `Enter` sends, `Shift+Enter` adds a line. The send button is disabled for empty or whitespace-only text. The limit is 1,000 characters, with a counter from 800.
- **FR-ASK-02** Suggestion chips (3 to 6) are made from the schema when a dataset loads, by the AI, with a template fallback such as "Missing values by column", "Top 5 <category> by <measure>" and "Trend of <measure> by month". Clicking a chip fills the box and sends.
- **FR-ASK-03** Each answer is a card with: a lavender tag chip ANSWER, one to three plain-English sentences with key numbers in bold monospace, a chart, a results table, a status row (Read-only verified pill, row count, run time, number of attempts, "Cleaned data" or "Raw data" badge) and the buttons Add to report, Copy SQL, Export CSV, "Explain this query" and thumbs up and down.
- **FR-ASK-04** The pipeline (Section 7) is: understand the question, write SQL, validate it with the read-only guard, run it, self-correct on failure, pick a chart, write the answer, and verify the numbers in the answer.
- **FR-ASK-05** While waiting, a skeleton card and a status line cycle through "Reading your schema", "Writing SQL", "Running query" and "Checking the answer". A Cancel button stops the request.
- **FR-ASK-06** The Self-correction card is a vertical stepper. Each attempt shows a number, a Failed (red) or Succeeded (green) pill, the problem in friendly words (for example "Column not found: churnrate") and what the AI changed. It updates live. A first-try success shows a single line "Succeeded on the first attempt".
- **FR-ASK-07** The Generated SQL card shows the final SQL, syntax highlighted, collapsible, with a Copy button. A "Show all attempts" toggle reveals the earlier failed SQL.
- **FR-ASK-08** The results table shows 10, 25, 50 or 100 rows per page, has a sticky header, sorts by column, formats numbers with separators, shows rates as percentages and blanks as a dash. If the result was cut at MAX_ROWS_RETURNED the table says so.
- **FR-ASK-09** Automatic chart choice:

| Result shape | Chart |
|---|---|
| One row, one number | Big number card |
| One category column and one number, up to 12 categories | Bar chart, sorted high to low |
| One category column and one number, more than 12 | Bar chart of the top 12 with a note |
| A date column and a number | Line chart |
| Two numeric columns | Scatter plot |
| A category with 6 or fewer values that are parts of a whole | Donut (also offered as a switch for bar results) |
| More than 3 columns, or no numeric column | Table only |

  The user can switch between the valid chart types for the result, or choose table only.
- **FR-ASK-10** The plain-English answer is written by the AI from the first 20 result rows. Code then checks that every number in the sentence appears in the results. If a number does not match, the AI sentence is replaced by a template sentence built by code.
- **FR-ASK-11** Only SQL is used. If a question needs something SQL cannot do (forecasting, machine learning), the AI says so and offers the closest SQL answer, for example the historical trend.
- **FR-ASK-12** "Add to report" saves the question, answer, top 20 rows and chart to the basket. The button turns into "Added" with a Remove option. The Report menu item shows the basket count.
- **FR-ASK-13** "Copy SQL" copies to the clipboard. "Export CSV" downloads every returned row as UTF-8 with BOM. Cells beginning with `=`, `+`, `-` or `@` get a leading apostrophe.
- **FR-ASK-14** Prompt injection defense: dataset text is placed in clearly marked data sections, the system prompt states that data text is untrusted and must never be followed as an instruction, and the read-only guard checks every generated query regardless of what the AI was told.
- **FR-ASK-15** Follow-up questions understand the last 5 exchanges in the conversation, for example "and only for 2024?". A "New chat" button clears that context. Conversations are saved to History.
- **FR-ASK-16** If the question could mean several columns or none, the AI asks one clarifying question with up to 4 tappable options. The chosen option is sent automatically.
- **FR-ASK-17** Questions unrelated to the data (weather, poems) get "I can only answer questions about your data", with suggestion chips.
- **FR-ASK-18** Requests to change data (delete, drop, update, insert, "remove all customers") are blocked before any SQL runs. A card says "Only read-only questions are allowed. DataPilot never changes your data." History records them as Blocked. The guard does the same if the AI itself produces such SQL.
- **FR-ASK-19** A query that returns zero rows shows "No rows matched", with suggestions such as "Show the distinct values of <column>" and "Remove the filter".
- **FR-ASK-20** If all 3 attempts fail, a Failed card shows a friendly message, a "Show technical details" toggle and the buttons "Rephrase", "Try again" and "Show me the columns". The stepper shows all failed attempts.
- **FR-ASK-21** A query running longer than SQL_TIMEOUT_SECONDS is stopped and counted as a failed attempt. The AI is told it was too slow and to aggregate or simplify.
- **FR-ASK-22** Only one question runs at a time. The input is disabled with a spinner while a question is in flight.
- **FR-ASK-23** API problems are classified as invalid key, rate limit, timeout or no network. Each has its own friendly message. Timeout and no-network messages offer a "Switch to Demo Mode" button.
- **FR-ASK-24** Before execution, a static check (an `EXPLAIN` of the query) confirms that every table and column named in the SQL exists. A bad name counts as a failed attempt immediately, which saves time.
- **FR-ASK-25** Multiple statements, comments, PRAGMA, ATTACH, DETACH, VACUUM, load_extension and any non-SELECT statement are blocked (Section 7.3).
- **FR-ASK-26** The conversation auto-scrolls to the newest answer. Each answer has a "Copy answer text" button.
- **FR-ASK-27** Non-English questions are answered in English, with a note.
- **FR-ASK-28** If no dataset is loaded, the page shows a card with a button to Upload.
