## 1. Introduction

### 1.1 Purpose
This document defines what DataPilot must do, how it must look, and how it must behave when things go wrong. It is written so an AI coding assistant can build the product milestone by milestone without asking questions.

### 1.2 The product in plain words
DataPilot is a smart assistant for messy business data. A person uploads a spreadsheet full of problems such as blanks, duplicates and inconsistent dates. DataPilot shows how healthy the data is and can clean it. The person then asks questions in plain English, for example "Which plan has the highest churn rate?". DataPilot writes the database query itself, runs it safely, fixes its own mistakes, and shows the answer as a sentence, a table and a chart. Finally it gathers everything into a report that can be shared with a manager.

### 1.3 Scope

**In scope**

- CSV and SQLite (.db, .sqlite) upload, plus built-in sample datasets
- Automatic data health check, and one-click cleaning with a before/after comparison
- Plain-English questions answered through validated, read-only SQL with automatic self-correction
- Automatic charts (bar, line, scatter, donut) and statistical outlier callouts
- Executive report builder with AI-written narrative, exported as Markdown and PDF
- Query history with re-run
- Three visual themes: Morning, Evening and Night
- Demo Mode, which works without internet

**Out of scope**

- User accounts, login, multi-user access, cloud deployment
- Excel (.xlsx) upload, files larger than 50 MB, live database connectors
- Modifying the original uploaded data (cleaning always creates a separate copy)
- Python code execution (all analysis is done through SQL; see FR-ASK-11)
- Non-English questions (best effort only, not tested)

### 1.4 Constraints

| Area | Constraint |
|---|---|
| Machine | TCS-issued Windows laptop. No software from outside; only pip packages that are allowed |
| Network | The only outside call allowed is the OpenAI API provided by the hackathon. No CDNs, no web fonts, no external images, no analytics |
| AI | OpenAI models through the hackathon key. Codex is used for development |
| Time | One day, about 9 working hours |
| Privacy | Only the table schema and a few sample rows are sent to OpenAI. The full dataset never leaves the laptop |
| Dependencies | Keep the list tiny: flask, pandas, openai. Everything else is standard library or written in the project |

### 1.5 Definitions

| Term | Meaning |
|---|---|
| Dataset | One uploaded file (or sample), stored locally and queryable |
| Health score | A 0 to 100 number summarizing data quality (formula in FR-DH-03) |
| Self-correction | When generated SQL fails, the error goes back to the AI, which retries, up to 3 attempts in total |
| Read-only guard | The set of checks that guarantees no question can change or delete data |
| Outlier | A value statistically far from the rest (method in FR-IN-04) |
| Active view | Whether questions run against the raw data or the cleaned copy |
| Theme | Morning, Evening or Night visual mode |
| Demo Mode | A switch that answers from pre-saved results so the demo works with no internet |
| Basket | The list of answers, charts and callouts the user has added for the report |

### 1.6 Risks and mitigations

| Risk | Mitigation |
|---|---|
| pip is blocked on the laptop | Test `pip install flask pandas openai` in the first 10 minutes of M0. If pandas is blocked, Codex rewrites the health and cleaning modules with the standard library (csv, statistics, sqlite3). Same features, more code |
| OpenAI API is slow, rate limited or down | Demo Mode (FR-SET-05) with pre-saved answers for the demo questions |
| The AI writes bad or dangerous SQL | Read-only guard plus self-correction loop (Section 7) |
| Time overrun | Milestones are priority ordered. The cut order is given in Section 12.2 |
| Style drift across pages | All colors, radii and spacing come from theme tokens (Section 4). No hard-coded colors in page code |
| Judges ask "is my data safe?" | Section 3.5 and the Settings privacy toggle (FR-SET-03) |

### 1.7 Assumptions
- The laptop has Python 3.10 or newer and a modern Chrome or Edge.
- The hackathon provides an OpenAI API key and tells you the model name.
- A single user runs the app locally on one machine.
- Sample data is synthetic, so no real customer data is involved.

## 2. Overall Description

### 2.1 Users

| Persona | Who | Needs |
|---|---|---|
| Priya, business manager | Non-technical, owns the numbers but cannot code | Plain-English answers, clear charts, a report she can forward |
| Arjun, data analyst | Technical, tired of boilerplate | Fast cleaning, visible SQL he can copy and trust |
| Hackathon judge | Watches a 5 minute demo | A clear story, a visible self-correction moment, a polished look |

### 2.2 End-to-end journey
1. Open the app. The theme matches the time of day.
2. On Upload, drop a CSV or click "Try sample dataset". See a summary and a preview.
3. On Data Health, see the score and the list of problems. Select fixes and click Auto-clean. Compare before and after.
4. On Ask AI, type a question. See the answer, table, chart, SQL and the self-correction steps.
5. On Insights, browse automatic charts and outlier callouts.
6. On Report, tick the sections to include, click Generate with AI, preview the document and download it.
7. On History, find any earlier question and re-run it or add it to the report.

## 3. System Architecture

### 3.1 Technology choices

| Layer | Choice | Reason |
|---|---|---|
| Backend | Python 3.10+, Flask 3 | Small, easy for Codex, runs on any laptop |
| Data | pandas, sqlite3 (standard library) | SQLite ships with Python, so no database server |
| AI | Official `openai` Python SDK | Key stays on the server, never in the browser |
| Frontend | HTML, CSS custom properties, vanilla JavaScript (ES modules) | No npm, no build step, nothing to download |
| Charts | Small SVG chart module written in the project (bar, line, scatter, donut, sparkline) | No chart library to install, full control of theme colors |
| Icons | Inline SVG sprite written in the project | No icon library |
| PDF | Browser print with a dedicated print stylesheet (Save as PDF) | No PDF library to install |
| Fonts | `Plus Jakarta Sans` if installed, else Segoe UI, system-ui. Mono: `JetBrains Mono` if installed, else Consolas | No web fonts allowed |

Streamlit is deliberately not used. It cannot produce the floating pill navigation and the three-theme look specified in Section 4.

### 3.2 Folder structure
```
datapilot/
  app.py                  # Flask entry point, routes
  config.py               # reads .env
  services/
    ingest.py             # CSV/SQLite loading, type detection, name normalizing
    health.py             # health checks, score, issue list
    cleaner.py            # cleaning rules, before/after, log
    nl2sql.py             # prompt building, LLM calls, self-correction loop
    sql_guard.py          # read-only validation and safe execution
    charts.py             # chart type picker, outlier detection
    report.py             # report assembly, Markdown export
    llm.py                # OpenAI wrapper, retries, Demo Mode
  static/
    css/ (tokens.css, themes.css, components.css, pages.css, print.css)
    js/  (app.js, api.js, theme.js, charts.js, pages/*.js)
    icons.svg
  templates/index.html    # single page shell
  storage/                # created at runtime: app.db, datasets/<id>/data.sqlite
  data/                   # generated sample data (Section 13)
  demo/cached_answers.json
  tests/
  generate_data.py
  .env.example  requirements.txt  README.md
```

### 3.3 Storage design
- `storage/app.db` holds the tables: datasets, health_snapshots, cleaning_runs, queries, pins, reports, settings (Section 8).
- Each dataset gets its own file `storage/datasets/<id>/data.sqlite` with three objects: table `<name>__raw` (original values, column names normalized to snake_case), table `<name>__clean` (created by Auto-clean), and a VIEW named `<name>` that points to whichever is active.
- The AI and the user always refer to the plain name `<name>`. Switching between raw and cleaned simply re-points the view.
- For an uploaded SQLite file, the file is copied as is and opened read-only. Cleaning a table creates `<table>__clean` in a separate sidecar file, never in the user's file.

### 3.4 Configuration (`.env`)

| Variable | Default | Purpose |
|---|---|---|
| OPENAI_API_KEY | none | Required unless Demo Mode is on |
| OPENAI_BASE_URL | empty | Set only if the hackathon gives a custom endpoint |
| OPENAI_MODEL | as provided | Model name used for all AI calls |
| MAX_UPLOAD_MB | 50 | Upload size limit |
| MAX_ROWS_RETURNED | 1000 | Row cap on any query result |
| SQL_TIMEOUT_SECONDS | 10 | Query time limit |
| MAX_SQL_ATTEMPTS | 3 | Total tries in the self-correction loop |
| SEND_SAMPLE_ROWS | true | If false, only column names and types go to OpenAI |
| DEMO_MODE | false | Answer from cached results |
| PORT | 5000 | Local port |

### 3.5 Security and privacy principles
1. The API key lives only in `.env` on the server. It is never sent to the browser and never logged.
2. Only the schema, column statistics and at most 5 sample rows are sent to OpenAI. With SEND_SAMPLE_ROWS=false, even the sample rows are withheld.
3. Query results are sent back to OpenAI only as the first 20 rows when writing a plain-English answer or narrative. With SEND_SAMPLE_ROWS=false, only aggregate numbers are sent.
4. The app listens on 127.0.0.1 only.
5. Uploaded file names are sanitized and never used as paths.
6. Text from the dataset is treated as data, never as instructions to the AI (FR-ASK-14).
7. Logs contain no dataset values and no API key.

## 4. UI and Design System (self-contained)

This section replaces any reference images. It describes the look completely in words, tokens and wireframes.

### 4.1 Visual identity in one paragraph
DataPilot looks friendly and premium, not like a generic grey dashboard. There is no left sidebar. A floating, rounded pill bar sits at the top. The page background is a soft gradient, not a flat color. Content sits on very rounded, slightly translucent cards with gentle shadows. Buttons are pills. Headlines mix regular and *italic* words. Numbers and data labels use a monospace font. Small uppercase tag chips and colored status pills add detail, and thin ring charts and thin progress bars keep things light. The product has three moods: Morning (airy pastel), Evening (warm purple with peach accents) and Night (near-black navy with periwinkle accents). The structure is identical in all three; only the tokens change.

### 4.3 Theme behavior
- **FR-UI-01** Three themes: Morning (sun icon), Evening (sunset icon), Night (moon icon).
- **FR-UI-02** On the first visit the theme is chosen by local time: Morning 05:00 to 15:59, Evening 16:00 to 19:59, Night 20:00 to 04:59.
- **FR-UI-03** A three-way segmented toggle (sun, sunset, moon) in the nav bar switches themes instantly. The choice is saved in the browser and overrides the time-based default. Settings offers "Auto (by time of day)" to go back.
- **FR-UI-04** Switching theme animates colors over 250 ms, unless the system asks for reduced motion, in which case it switches instantly.
- **FR-UI-05** All charts, the code block, tables and status pills re-color with the theme. The chart module reads the --chart-N tokens at draw time and re-draws on theme change.
- **FR-UI-06** The print stylesheet always uses a clean white page, whatever the active theme.

### 4.5 Chart style (applies to every chart)
- Bars have rounded tops, a 12 px gap and one color per category from --chart-1 to --chart-5 (the highest or most important bar may use --chart-3, the coral or danger-like tone, so it stands out).
- The value is printed above each bar in monospace bold. The y axis shows 4 to 5 faint gridlines with muted monospace labels.
- Lines are 3 px, smooth, with a soft area fill at 15% opacity and a dot on the last point. Scatter points are 6 px with 70% opacity, and outliers are --danger with a ring.
- Donuts are thin rings (stroke 14 px) with the main number centered in monospace.
- A hover tooltip shows the exact values. Charts draw in 400 ms.

### 4.7 Responsive and accessibility
- **FR-UI-07** Designed for 1280 px and wider. Between 1024 and 1279 px cards reflow to fewer columns. Below 1024 px the nav menu shows icons only and columns stack.
- **FR-UI-08** Text contrast is at least 4.5 to 1 in all three themes. Status is never shown by color alone (an icon or label always accompanies it).
- **FR-UI-09** Everything is reachable by keyboard with a visible focus ring. The AI answer area uses `aria-live` so screen readers announce new answers. Charts have a text summary (`aria-label`) and a "View as table" option.

## 5. Global Application Requirements

- **FR-GL-01** Single-page app shell. Pages are routed by URL hash (`#/upload`, `#/health`, `#/ask`, `#/insights`, `#/report`, `#/history`). The browser back and forward buttons work.
- **FR-GL-02** With no dataset loaded, Data Health, Ask AI, Insights and Report are greyed out with the tooltip "Upload a dataset first". Upload and History are always available.
- **FR-GL-03** The dataset chip in the nav shows the active dataset name and row count. Its dropdown lists all datasets (switch, rename, delete) and "Upload new". The last active dataset is restored after a reload.
- **FR-GL-04** Toasts: success, info, warning, error. Success and info disappear after 5 seconds. Errors stay until closed.
- **FR-GL-05** A thin progress bar shows at the top for any request longer than 300 ms. Every data area has a skeleton loading state.
- **FR-GL-06** If the browser cannot reach the server, a banner says "Lost connection to DataPilot" with a Retry button. The app recovers on its own when the server returns.
- **FR-GL-07** An unknown route shows a friendly "Page not found" card inside the normal shell with a button back to Upload.
- **FR-GL-08** A "Demo Mode" badge appears in the nav whenever Demo Mode is on.
- **FR-GL-09** When the active view is raw and the health score is below 90, Ask AI, Insights and Report show a slim banner: "You are working with uncleaned data. Results may be unreliable." with a "Switch to cleaned data" button (or "Go to Data Health" if no clean copy exists yet).
- **FR-GL-10** Keyboard shortcuts: `/` focuses the question box on Ask AI, `Ctrl+Enter` sends, `Esc` closes any drawer or modal.
- **FR-GL-11** Every page and every data panel defines four states: loading, empty, error and normal. No panel may show a blank area or a raw error message.
- **FR-GL-12** Every user-facing error is plain English with one suggested next action. Technical details sit behind a "Show details" toggle.
- **FR-GL-13** Closing and reopening the tab, or restarting the server, keeps datasets, history and reports.
- **FR-GL-14** Report basket count appears as a small badge on the Report menu item.
