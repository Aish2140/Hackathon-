## 9. Non-Functional Requirements

| ID | Area | Requirement |
|---|---|---|
| NFR-01 | Performance | Upload and parse 50,000 rows in 5 s. Health check in 3 s. Insights page in 3 s. Any page navigation under 300 ms |
| NFR-02 | Performance | A question is answered in under 15 s in normal conditions (the AI call dominates). The first status text appears within 500 ms |
| NFR-03 | Reliability | No unhandled exception reaches the user. Every failure path ends in a friendly message |
| NFR-04 | Data safety | The raw data and the original file are never modified. The app works on copies |
| NFR-05 | Security | The server binds to 127.0.0.1. The key is never exposed. The read-only guard has five layers (7.3) |
| NFR-06 | Privacy | Only schema, statistics and at most 5 sample rows go to the AI (3.5) |
| NFR-07 | Portability | Runs on Windows 10 or 11, Python 3.10+, Chrome or Edge (latest). Setup is at most 5 commands, documented in the README |
| NFR-08 | Offline | Everything except live AI calls works with no internet. Demo Mode covers the AI features |
| NFR-09 | Usability | A first-time user completes upload, question and report without instructions |
| NFR-10 | Accessibility | FR-UI-07 to FR-UI-09. Text contrast of 4.5 to 1 in all themes |
| NFR-11 | Maintainability | Each service module has one job (3.2). No file over 600 lines. No raw colors outside the theme files |
| NFR-12 | Logging | A local `datapilot.log` records events, timings and error types. It never contains dataset values or the key |
| NFR-13 | Consistency | The same question on the same data yields the same SQL (temperature 0) |
| NFR-14 | Recoverability | Deleting `storage/` resets the app cleanly. Sample data regenerates from the script |

### 10.1 Upload and ingest

### 10.2 Health and cleaning

| # | Situation | Expected behavior |
|---|---|---|
| H1 | Column is 100% blank | Flagged near-empty; excluded from outlier and type checks |
| H2 | Constant column | Flagged, not removed |
| H3 | All values unique in a text column | Treated as ID-like, no category merging |
| H4 | Ambiguous dates (03/04/2024) | Majority rule, else day-first with Review note |
| H5 | Two-digit years | 00 to 49 means 2000s, 50 to 99 means 1900s, flagged Review |
| H6 | Case variants "Pro", "pro", "PRO " | Merged to the most frequent form |
| H7 | Two forms equally frequent | Merge to the longer form, note in log |
| H8 | Booleans as Yes/No/Y/N/1/0/True/False | Standardized to 1 and 0 |
| H9 | Placeholder text in numeric column ("N/A") | Becomes blank, column becomes numeric |
| H10 | Negative where not allowed | Flagged; fixed only if the Review fix is ticked |
| H11 | Churn date before signup date | Flagged as logical error |
| H12 | Dataset under 20 rows | Reliability warning; outlier checks skipped |
| H13 | Clean run with no fixes ticked | Button disabled |
| H14 | Clean run twice | Identical result |
| H15 | Clean cancelled | No partial table |
| H16 | Duplicate rows differing only in whitespace or case | Found after trimming and merging (fix order matters, FR-DH-08) |
| H17 | Cleaning removes every row | Aborted with an error; nothing saved |
| H18 | Raw and clean both exist and user uploads a new file | Old pair stays with its dataset |

## 11. Test Plan and Golden Questions

### 11.1 Test layers
1. **Unit tests** (pytest if available, otherwise `unittest`): sql_guard (every blocked word, comments, multi-statement, string-literal false positives), name normalization, type detection, date parsing, each cleaning fix, health score formula, outlier detection, chart picker, number verification.
